C1 TYPE: COUNTING-RULE
C1 ARMS: Same ByteTrack tracks per detector (YOLOv5m-4D RGB-D, YOLOv5m RGB, CenterNet); arms: count the largest track ID (Max ID) vs the authors' tracking-region rule (an ID is counted once when it crosses between outside and inside a region)
C1 RESULTS: Per video, true / Max ID / region count. YOLOv5m-4D: 167 / 290 / 173; 128 / 318 / 124; 91 / 145 / 96; 143 / 324 / 132. YOLOv5m: 167 / 313 / 184; 128 / 339 / 131; 91 / 155 / 102; 143 / 357 / 151. CenterNet: 167 / 324 / 187; 128 / 347 / 137; 91 / 151 / 100; 143 / 361 / 155. The region rule is closer to the true count in every video and detector (Max ID is 1.59 to 2.71 times the true count by my calculation from the printed values). Mean counting accuracy of the region rule: 95.1% (YOLOv5m-4D), 92.6% (YOLOv5m), 90.6% (CenterNet). Max ID counting accuracy not reported. MOTA for the same tracks: 0.84, 0.79, 0.89, 0.81 (4D); 0.76, 0.74, 0.85, 0.73 (YOLOv5m); 0.73, 0.69, 0.86, 0.71 (CenterNet)
C1 WHERE: Table 3, lines 795-875; text lines 759-791
C1 QUOTE: "Therefore, it was inaccurate to adopt max IDs counted as the yield result." (lines 779-780)
C1 AUTHORS' EXPLANATION: ID shift comes from large variation of cluster features between viewpoints and from false-positive clusters in a frame; the region rule limits repeated counting after ID switches; remaining error (4.9%) from missed detections in the middle region and ID shifts after entering the region (lines 772-777, 917-923)
C1 CONDITIONS: greenhouse with dense ridges, 30 FPS, robot speed 0.15 m/s; background clusters from the opposite ridge raise Max ID
