KEY: naftali2024palm
(Naftali, Hugo, Suharjito. "Palm Oil Counter: State-of-the-Art Deep Learning Models for Detection and Counting in Plantations." IEEE Access vol. 12, 2024. DOI 10.1109/ACCESS.2024.3419835.)

CROP / SETTING / SCALE: Oil palm fresh fruit bunches (FFBs) still attached to trees, plantation setting in Central Kalimantan, Indonesia (Introduction; II.A; Conclusion l.1809-1820). Dataset: 440 videos (II.A, quoted K14). Number of trees, bunches and images in total: not stated in the text read. Table 1 (class distribution by object): not stated in the text read; the table body was not visible in the extracted text.

ACQUISITION: Video along the tree, handheld or platform not stated. 440 videos at 30 fps, MP4, 320 x 640 pixels, portrait orientation (II.A, K11; Contribution 1). Video length 8 seconds to 1 minute 31 seconds (K14). Camera model, distance, number of sides of the row, and frame rate in relation to the tree: not stated. Frames extracted with CVAT; frames with blue tint or distortion removed by hand (II.B Step 1). Algorithm 1 keeps a frame only when "frame quality is acceptable and not similar to the last" (II.B, Algorithm 1, K13). Single-view versus multi-view capture: not stated; each video is treated as a sequence of frames.

OBSERVATION / DETECTOR: Single-stage YOLO detectors on each frame. Main model: YOLOv8s Depthwise, in which standard convolutions are replaced by depthwise separable convolutions (II.C). Reported parameter reductions from the authors' own architecture calculation: 84.589% for the convolution block, 42.25% for the detect head, and 50.65% for the "C2f Ghost" block (II.C, K21, K22). Comparators trained on the same data: YOLOv6s, YOLOv6l, YOLOv7 tiny, YOLOv7l, YOLOv8s, YOLOv8l (III.D, Algorithm 3). Input size: 640 x 640 for training and inference (Algorithm 4, K29), while the videos are 320 x 640 (K11); the reason for the difference is not stated. Five detected classes: unripe, underripe, ripe, flower, abnormal. Detection accuracy (valid frames only, validation phase): YOLOv8s Depthwise mAP50 0.75, mAP50-95 0.481 (Abstract, K2; Table 7 text). Variants and versions: YOLOv6 (EfficientRep, RepOptimizer, PAN, TOOD label assignment, VariFocal loss); YOLOv7 (E-ELAN, RepConvN, EMA); YOLOv8 (C2f, SPPF, FPN+PAN, CIoU+DFL, BCE). Framework MMYOLO (OpenMMLab) on Google Colaboratory with NVIDIA V100 for training, NVIDIA T4 for inference with ONNX Runtime (III.D, K28). Abstract names YOLOv9 as a comparator; no YOLOv9 result appears in any table read.

ASSOCIATION METHOD: None. The paper does not link detections across frames, videos, or views. Counting is done per frame by Algorithm 2 CountOilPalmPerFrame, which takes "boundingBoxes, IoUThreshold" as input and returns "countDataPerClass" (II.C, K23). For each box with "boundingBox. IoU > IoUThreshold" the count for its class is increased. The IoU reference against which the threshold is applied is not stated. The paper does not describe a tracker, a unique ID, or a counting line. The CVAT "track" feature is used during annotation only (II.B Step 2, K15). Counting at inference is described as: "the enumeration process will be handled simultaneously while the detection is being run" (II.C, K18).

ASSUMPTIONS STATED OR IMPLIED BY AUTHORS:
- Each detected object in a frame is one bunch: "the number of each object in a frame is quantified" (II.C, K20).
- Counting accuracy in a frame is taken to reflect counting accuracy for the tree, which is not stated or tested.
- The "same object" issue is treated as a detection problem only (Figure 10, see below).
- Dataset splits by video source avoid temporal redundancy: "We ensure no overlap of videos between training, validation, and testing datasets, avoiding temporal information redundancy." (II.B Step 4, K16).
- Undersampling frames with high visual similarity is assumed to remove redundancy (II.B Step 5, K17).
- The authors state that prior counting work "only addresses classification" in a 2024 plantation study (Introduction, K8).

DOUBLE-COUNT SOURCES ADDRESSED:
(a) Same fruit in consecutive frames: not addressed in the method. The Algorithm 1 similarity filter (K13) drops similar frames during frame extraction only, and the paper does not say this removes double counting at the counting stage. Figure 10(a) reports this failure without a mechanism: "Figure 10(a) illustrates instances where the same object is counted twice, highlighting potential challenges in the detection process." (Results, Figure 10, K46). No frequency is given.
(b) Track lost and restarted: not applicable; no track is maintained.
(c) Same fruit from both sides or different passes: not addressed. Only one video orientation (portrait, 320 x 640) is described; no multi-side or multi-pass capture is mentioned.
Other failure in Figure 10(b): "a model fails to detect one object" (Results, Figure 10). No frequency is given for either failure type.

CLASS / MATURITY HANDLING: Five classes: unripe, underripe, ripe, flower, abnormal (Abstract, K1). Class definitions in II.A: Unripe (blackish blue), Underripe (dark purple to dark red), Ripe (dark red to bright red, often with yellow spots), Flower (no fruit, long brown fibers), Abnormal (irregular shape, fewer fruits). Class per bunch is the detector's single output label; it is not linked across frames. How a class is assigned when frames disagree: not stated, because there is no cross-frame link. Class imbalance is handled with a class weight, w_new = 1 - n_class / n_total (Persamaan 1, E.1), which lowers the weight of the majority class "Unripe" (K30), plus manual undersampling of the majority class (II.B Step 5). Class-wise split (II.B Step 4). Label assignment per class is in the detector output. Authors state that "one class may resemble another" under blur and low contrast (K10).

COUNT REFERENCE AND METRIC LEVEL:
- Count reference: ground-truth number of bounding boxes per class per image in the annotated frames (not a hand count on the tree, not a harvest or packhouse count). This is inferred from the metric definition: MAE and RMSE compare G_i (ground truth) with P_i(tau) (predicted count above threshold tau) over N images (E.5, E.6, K36).
- Count metrics: per-class MAE (Eq 21) and RMSE (Eq 23) over N images; overall value is the mean across classes (Eq 22, 24). "Across all images employed in the counting process, the evaluation employs metrics such as MAE and RMSE [89]." (F, K36). Counting is evaluated "within individual frames" (K35).
- Detection metrics: AP, mAP, mAP50, mAP50-95, mAR (Eq 15-20). Text states "we can determine the value of mAP with Equation (17)" (F.2, K38), but Equation (18) is the one printed with mAP.
- Identity metrics (MOTA, IDF1, HOTA, ID switches): not stated; not applicable.
- Evaluation on validation set during training (F, "the evaluation conducted during the validation phase"); test split results are not separately described in the text read.

- Training time per model (Gambar 9, l.1617-1647): YOLOv6l 8 h 16 min 20 s; YOLOv6s 3 h 30 min 4 s; YOLOv7l 7 h 32 min 59 s; YOLOv7 tiny 3 h 30 min 3 s; YOLOv8l 5 h 12 min 15 s; YOLOv8s 2 h 39 min 41 s; YOLOv8s Depthwise 2 h 18 min 30 s.
- Table 4 (per class, Results l.1540-1566): YOLOv6s AP50 0.874 and AP50-95 0.543 for Abnormal (K40). YOLOv7 tiny MAE 0.064 and RMSE 0.253 for Abnormal (K41); MAE 0.105 and RMSE 0.323 for Flower (l.1551-1554). Values for YOLOv8s Depthwise on these classes are not given in the text.
- Table 2 (with augmentation) and Table 3 (without augmentation): values not visible in the extracted text. YOLOv6l is stated to be best in mAP50, mAP50-95, and mAR50-95 with and without augmentation (l.1522-1531). Augmentation raises mAP50 and mAP50-95 for all models; effects on mAR50-95, MAE, RMSE are "relatively insubstantial" (l.1532-1535).
- Model size (l.1567-1573): YOLOv8s Depthwise 21.2 MB; YOLOv6l 223.7 MB; YOLOv8l 174.5 MB. "With a size of just 21.2 MB, it is the smallest among all the models evaluated" (K42).
- Table 5 (tuning of YOLOv8s Depthwise, l.1585-1600): Adam stable at 0.0001 and 0.001; performance drops at 0.01. SGD learning rate 0.001 optimal; 0.0001 with SGD "resulted in inadequate learning" (l.1595-1600). Table 5 numbers not visible in the text.
- Quantization (l.1673-1726): mAP50 and mAP50-95 difference "as little as 0.001". Inference time, original vs fp16: YOLOv6l 0.0632 s to 0.0378 s; YOLOv7 tiny 0.0248 s to 0.0219 s; YOLOv8l 0.055 s to 0.0314 s (l.1690-1699). YOLOv8s Depthwise 0.027 s (quantized) vs 0.0275 s (non-quantized) (l.1702-1726). Size 21.2 MB to 10.6 MB.
- Table 7 (plantation dataset, l.1727-1755): SSD MobileNetV2 inference 0.024 s, mAP50 0.546, mAP50-95 0.306, MAE 0.321, RMSE 0.543. YOLOv8s mAP50 0.759, mAP50-95 0.5, size 22.3 MB. Faster RCNN mAP50 0.743, inference 0.0497 s, size 165.4 MB (K48). YOLOv4 mAP50 0.787, mAP50-95 0.513, inference 0.048 s, size 244.3 MB. YOLOv8s Depthwise size 10.6 MB, inference 0.027 s, mAP50 0.75, mAP50-95 0.481, MAE 0.164, RMSE 0.4.
- Table 8 (harvested fruit dataset from prior work [3], l.1756-1786): YOLOv8s Depthwise inference 0.026 s, mAP50 0.994, mAP50-95 0.875, size 10.6 MB (K50). EfficientDet-D0 inference 0.03 s, mAP50 0.993, mAP50-95 0.871, size 40.1 MB. YOLOv4 inference 0.042 s, mAP50 0.985, mAP50-95 0.743, size 244.3 MB. SSD MobileNetV2 inference 0.027 s, size 12.3 MB. No MAE or RMSE given for Table 8.
- Counting on the plantation set: MAE 0.164 and RMSE 0.4 for YOLOv8s Depthwise (K3). No counting error is reported for the harvested dataset.
- Web application (l.1787-1800): an example frame counted "two instances of unripe fruits, one instance of an abnormal fruit, and one instance of an underripe fruit" (K56). No counting accuracy is given for this example.

FAILURE CONDITIONS / ERROR SOURCES REPORTED:
- Overlapping bunches, tight clusters, and obstructed views (occlusion) (Introduction, K5).
- Partially visible objects, low contrast scenes, occluded and small objects, blurry images (Abstract, K1).
- Slight blur and reduced contrast cause one class to resemble another (II.A, K10).
- Long camera distance (II.A challenges list, l.201-400 notes).
- Double counting of the same object (Figure 10(a), K46).
- Missed detection of one object (Figure 10(b)).
- Low learning rate with SGD gives "inadequate learning" (Table 5, l.1595-1600).
- Lower-accuracy results for Adam at learning rate 0.01 (Table 5, l.1589-1594).
- Batch size 16 set by "computational limitations of our testing bench" (III.D, K25).
- Authors' stated limit on generalization: dataset "limited to the specific conditions of the Central Kalimantan Province" (K52).

COMPARISONS ON THE SAME DATA:
- Plantation dataset (Table 7): YOLOv8s Depthwise against Faster RCNN, SSD MobileNetV2, YOLOv4, YOLOv8s. The text claims superiority in speed, accuracy, and efficiency (K54), but the table values are: YOLOv4 mAP50 0.787 and YOLOv8s 0.759 are above YOLOv8s Depthwise 0.75; SSD MobileNetV2 inference 0.024 s is faster than 0.027 s. Faster RCNN mAP50 0.743 is below YOLOv8s Depthwise.
- Harvested dataset (Table 8, from prior work [3]): YOLOv8s Depthwise is highest on mAP50 (0.994) and mAP50-95 (0.875), against EfficientDet-D0 (0.993, 0.871), YOLOv4 (0.985, 0.743). "the YOLOv8s Depthwise model excels with an mAP50 of 0.994 and an mAP50-95 of 0.875, the highest among the compared models." (K50). The Table 8 comparison is on a different dataset from Table 7.
- Abstract lists YOLOv9 as a comparator on the same data; no YOLOv9 entry appears in any table read. The next sentence of the Abstract names EfficientDet-D0 "from previous research", so same-data and prior-work comparisons are not separated.
- Within YOLO variants (Table 4 and text): YOLOv6s best on AP for Abnormal; YOLOv7 tiny lowest MAE and RMSE for Abnormal and Flower (K40, K41). Authors' recommendation: YOLOv6 for detection accuracy, YOLOv7 for low MAE/RMSE, YOLOv8s Depthwise as "balanced" (l.1575-1584).

AUTHORS' STATED LIMITATIONS / FUTURE WORK:
- "The dataset, while comprehensive, is limited to the specific conditions of the Central Kalimantan Province in Indonesia." (K52). Other conditions named: environmental variation, oil palm species, cultivation practices; hardware challenges; network connectivity for the web application; need for retraining (l.1861-1871).
- "Future work will focus on addressing these limitations, expanding the dataset, and further optimizing the model for diverse agricultural environments." (K53). Also named: use of YOLO for crop monitoring, pest detection, yield estimation, and precision agriculture (l.1878-1883).
- Planned but not reported: depthwise separable model training after fine-tuning; learning rates 0.0001, 0.001, 0.01 with SGD and Adam (K26, K27). Their results are not in the text read.

INCONSISTENCIES INSIDE THE PAPER:
1. Conclusion claims superiority in speed and accuracy (K54, l.1832-1841), but Table 7 values show YOLOv4 mAP50 0.787 and YOLOv8s 0.759 above YOLOv8s Depthwise 0.75, and SSD MobileNetV2 inference 0.024 s below 0.027 s.
2. Quantization effect on inference time, same paragraph: "Quantization to fp16 consistently resulted in a negligible increase in inference time" (l.1601-1606, K45) against "inference time was notably reduced" (l.1690-1699) and "relatively small reduction" (l.1708-1709). Direction of the change is contradictory.
3. Conclusion gives "0.0275s to 0.0273s" (l.1828-1831, K55), while the results text gives "0,027 s (quantized)" and "0,0275 s (non-quantized)" (l.1702-1726). Order and rounding differ.
4. Quantization described as "during training" (E.6, l.1253-1254, K37), but FP16 conversion is described at deployment with ONNX Runtime (l.719-731).
5. Input resolution: videos are "320 × 640 pixels" (II.A, K11); inference resizes to "640 × 640" (Algorithm 4, K29). Reason not given.
6. mAP equation: text says "we can determine the value of mAP with Equation (17)" (F.2, K38), but mAP is printed as Equation (18) (l.1338-1344).
7. Module naming: the block is called "C2f DW Separable Block" (l.683-690) and also "C2f Ghost" in the text (l.689-690, K22).
8. Table 7 SSD MobileNetV2 inference 0.024 s (plantation) vs Table 8 0.027 s (harvested); no explanation given.
9. Abstract comparators (Faster RCNN, SSD MobileNetV2, YOLOv4, YOLOv9) vs. the tables: YOLOv9 absent.
10. Equation 2 (VFL): the text defines "q is the target score" (l.1116-1118), but q does not appear in the extracted Equation 2.
11. Several table values (Tables 2-5, 6-8) appear only as text in the extraction; table cells were not visible, so the cell values could not be checked.
