Abstract – Manual counting of fruits to estimate yield is a 
cumbersome task that requires many laborers and may 
be prone to human error. Wrong counting may lead to 
financial losses and field mismanagement. To mitigate 
this problem, there is a need for technological solutions to 
count the fruits using computer vision and deep learning 
techniques. The technological solution using computer 
vision avoids manual counting errors, optimizes time, 
reduces the number of laborers needed for manual 
counting, and provides instant yield predictions. 
Moreover, counting images may lead to the same fruit 
being counted twice or more across different images. To 
avoid this, there is a need for a spatiotemporal solution 
that avoids counting the same fruit more than once. This 
paper initially focuses on fruit detection using the YOLO 
framework. Then it implements an object-tracking 
module to reduce the risk of counting the same fruit more 
than once. Finally, the object counter module is developed 
to count the number of fruits. Our results show that our 
model achieved 90% accuracy, 0.78 mAP, and 0.73 F1 
score, demonstrating significant improvements of 33% in 
mAP and 71% in F1 score compared to using YOLOv11 
alone.  Different multi-object tracking methods achieve 
substantial improvements in MAE for frame counting 
across all videos. These results show that our system has 
the potential to improve fruit yield assessment methods. 
     Keywords –Yield Estimation, Manual Counting, Computer 
Vision, Human Error, Resource Optimization, Multi-Object 
Tracking, Accuracy Improvement.

(ii) YOLO11
YOLO is an acronym for  ‘You Only Look Once’.
YOLO11 is a fast and effective algorithm for detecting 
objects. It is implemented on the frames generated from the 
real-time feed or a pre-recorded video. As each frame is 
processed, the fruits are detected and bounding boxes are 
generated around them. It then labels the class of each 
bounding box and provides a confidence score for each object 
detected. Even in case of fruit occlusions, YOLO11 can 
accurately identify and locate the fruits, making it an integral 
part of the proposed system. 
(iii) ByteTracker
After YOLO11 detects the fruits in each frame,
ByteTracker takes over to track these fruits as they move 
across frames. ByteTracker uses data from YOLO to keep 
track of the same fruits across different frames. It assigns a 
unique ID to each fruit, ensuring that the same fruit is not 
counted multiple times or confused with another. Even when 
fruits move or become occluded (hidden behind other 
objects), ByteTracker ensures that the system continues to 
track them accurately. It also integrates a counting algorithm 
to tally the tracking. This is critical for long-term fruit 
tracking in a video feed, as the system can maintain a 
consistent count of the fruits, regardless of how they move or 
overlap with each other.

A.
Capture Module
The Capture Module is responsible for acquiring video
footage, which serves as input for the apple detection and
tracking system. The input is obtained from two primary
sources:
(i) Real Time Drone Video Feed
A 360-degree rotating drone forms a circle around an
apple tree that records live video from various angles. Due to 
its high-resolution camera, the drone is capable of easily 
observing apples under different lighting conditions. Real-
time video streaming to the processing module allows for 
immediate tracking and detection. 
(ii) Stored Video Footage
The system also supports pre-recorded videos read from a
stored file using OpenCV and the video properties such as 
frame width, height, and frame rate are extracted for 
processing. These parameters ensure that the system adjusts 
to different video formats. Before their deployment on live 
feed drone streams, these videos help optimize the YOLO11 
model and tracking algorithms. Frame-by-frame processing 
is done on the video that has been stored. 
The captured frames from both sources are passed to the 
detection module. 
B.
Object Detection
The Object Detection module identifies apples in video
frames captured from a drone feed. It does this by using
YOLO11, the most advanced deep learning model, to detect
and locate objects in real time. It extracts all important visual
features like color, shape, and texture to distinguish apples
from leaves, branches, or other objects. The model can
identify various fruits based on these properties. This purely
model based algorithm will detect any type of fruit once
trained with its data. We can train the model with the type of
fruit we are trying to detect. Since it has been trained over a
custom dataset on apples, this model is specialized towards
detecting apples under conditions such as different angles,
occlusions, lighting variations.
(i) Dataset of Training Apple Images
A diverse dataset of fruit images and videos is curated
from various agricultural settings which contains thousands 
of images of apples that were used to train the model. The 
dataset was annotated using bounding boxes to mark apples 
in images. The model was trained using transfer learning on 
a pre-trained YOLO11 base model. 
(ii) Object Detection
After receiving a video frame from the Capture Module,
the YOLOv11 model processes the frame and identifies 
apples. A region of interest (ROI) is defined to restrict 
detection to relevant areas in the video which ensures that 
detection occurs within the full frame, but it can be adjusted 
to focus on specific areas if needed. It generates bounding 
boxes around detected apples. Each detected apple is 
assigned a confidence score. Apples are rejected with less 
than a given confidence value (for example, 70%).After 
detection, apples are assigned unique tracking IDs, which are 
then used in the Tracking Module for further processing.

C. Tracking Processor 
The key application of the object tracker is the counting of 
apples over frames. This tracker can be implemented using 
various approaches but there is one tracker that suits our use 
case better than any. Various trackers are employed to check 
their compatibility with the model and their accuracy in 
performing the job. From them ByteTracker is considered as 
the most compatible option that best fits the job 
scheduled.  ByteTracker has higher accuracy in tracking 
objects with similar properties and has a plugin that is 
developed inside YOLO to connect and operate with the 
model directly. Various trackers that we used in our search 
for best trackers are mentioned below. 
 
i. SORT (Simple Online Real-Time Tracker) 
     SORT is an efficient and lightweight tracking algorithm 
that uses Kalman Filters for motion prediction and the 
Hungarian Algorithm for data association. This algorithm 
performs well in non-occluded environments but fails with 
occluded environments, leading to frequent ID switches. A 
more robust tracker is required  for real-world orchard 
conditions because of these limitations. 
 
ii. DeepSORT (Deep Simple Online Real-Time Tracker) 
     DeepSORT extends SORT by incorporating deep 
learning-based appearance descriptors for better re-
identification  of objects across frames. It enhances the 
performance in the case where the object is temporarily out 
of view (occlusion).In this context DeepSORT is not very 
efficient in the case of smaller  objects, like apples because it 
requires a lot of visual information to create feature 
embeddings. The computational cost is more which rules out 
its real-time usability in the systems with limited resources. 
 
(iii) ByteTracker (Byte-Track Improved SORT) 
     ByteTracker refines SORT by removing low-confidence 
detections because the fruit images can be detected as small 
objects, which normally have a lower detection score. 
Tracking apples in a complex environment has its own 
difficulties such as: Occlusion, as apples can be covered by 
leaves or branches. Small object size is difficult for the 
conventional trackers to maintain consistent IDs. ByteTrack 
overcomes these issues by employing a two-stage association 
strategy: 
a. Primary Association: Associate high-confidence 
detection to tracks using the motion estimation 
(Kalman Filters) 
b. Secondary Association: Incorporate the low 
confidence detections without losing apples due to 
occlusion or weak detections. 
This reduces the ID switches significantly and is much more 
robust for dense tracking in orchards. Furthermore, it still is 
computationally efficient enough that it remains the  choice 
for this.

D. Object Counter 
The Object Counter module is responsible for estimating the 
total number of apples on the tree by integrating the tracking 
data from ByteTracker with a counting algorithm. This 
module ensures that each apple is counted only once, 
preventing overcounting due to movement, occlusion, or 
reappearance in different frames.   
The difficulties in counting apples from a rotating drone 
video include Occlusions, Duplicate Counting, Motion 
Variability, Lighting and Shadows. The Object Counter 
overcomes all these with the use of Tracking based counting.  
(i) Integration of the Counting Algorithm 
     The algorithm for counting analyzes the tracking history 
of each apple that has been detected in consecutive frames. 
Whenever an apple first appears, the tracking algorithm 
assigns it a unique ID (ByteTracker). The tracking processor 
retrieves object details, such as bounding boxes, tracking IDs, 
and class labels; the counting algorithm checks whether it is 
a new tracking ID before actually counting each detected 
apple, meaning that the same apple, which has been detected 
several times, will not be counted multiple times. If an apple 
stays in the frame, its ID is maintained so that it is not counted 
twice. If an apple goes out of view for a few frames and then 
reappears, the tracker tries to reconnect it with the same ID 
rather than assigning a new one. The count is only updated 
when the apple is found to be unique based on track ID and 
location.

Real-time Apple Count display

IV. RESULTS 
4.1 Dataset and Model Training 
The model is trained using the dataset: Fruits-360 
dataset(https://www.kaggle.com/datasets/moltean/fruits): A 
dataset of images containing fruits, vegetables, nuts and 
seeds. The dataset has 126305 images of different fruits and 
more. Out of which, 7571 images are filtered out for training 
and testing the model. Each image is annotated in YOLOv11 
format. Each image was augmented with random rotation, 
cropping (up to 55%), and Gaussian blur to improve model 
performance. The dataset is divided into training (6,056 
images, 80%), validation (605 images, 8%), and test (910 
images, 12%) sets for effective learning and evaluation.  
     The model was trained for 200 epochs using input images 
resized to 640×640 pixels and halted at 150 epochs to prevent 
overfitting. A batch size of 4 was employed, with the workers 
parameter set to 4 to enable parallel data loading. The training 
utilized the default learning rate of 0.01. The training was 
done on an NVIDIA RTX 4060 GPU. 
Fig. 3 shows the Training loss curves and Fig. 4 shows the 
validation loss curves. The training loss and validation loss 
initially decrease, indicating good learning. But the validation 
loss plateaus at epoch 150 while the training loss continues to 
decrease, indicating overfitting. To prevent this, the training 
is terminated at epoch 150 because additional training can 
degrade generalization performance on new data.

In the system, fruit counting is performed by tracking each 
detected fruit across frames using unique identifiers (IDs). 
The system counts a fruit only when its ID is retained and 
crosses a defined region of interest (ROI) with some special 
conditions mentioned in methodology section. Therefore, the 
accuracy of the counting mechanism is highly dependent on 
the consistency and reliability of the tracking algorithm. 
Any  loss or switch in ID will result in either an undercount 
i.e. if a fruit is no longer tracked before reaching the ROI or
an overcount (if the same fruit is assigned multiple IDs). The
counting efficiency is therefore directly proportional to that
of tracking. With high tracking efficiency-reported in
retained IDs and low switch/loss rates-it can be guaranteed
that the majority of fruits are being counted correctly, once,
and at the right time. The accuracy of counting in the system
therefore closely follows the tracking performance, both with
average efficiencies of over 90%.

V. CONCLUSION
    This work presents a cost-effective approach to automate 
fruit detection and counting with YOLOv11 for object 
detection and ByteTracker for tracking. The proposed system 
is able to reduce the error in counting the fruits more than 
once with meticulous pipeline workflow, where it initially 
detects fruits, the track them with a subsequent counting 
module. This pipeline is successful in identifying fruits from 
dense tree setting obtained through real time drone videos. 
The accurate yield estimation of fruits improves farming 
decisions. The proposed system can be deployed for 
identifying and counting the different varieties of fruits, but 
the success of such models depends on how well the 
respective data set is.  
Even though the proposed model performs well for varying 
conditions, it may not be very effective in extreme weather 
conditions with heavy rain, dense fog and high winds. Still 
the more robust algorithms need to be developed to handle 
densely overlapped fruits in the natural scenes, otherwise the 
fruit counting may lead to the yield. To mitigate the said 
problem the latest techniques like vision transformers, 
attention-based mechanisms etc. may be employed. Further, 
the robust models can be extended to multiple fruit and hybrid 
farming too.
